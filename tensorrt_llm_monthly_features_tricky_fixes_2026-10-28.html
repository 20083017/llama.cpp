KV Cache V2 成为核心统一管理、Mooncake、host tier、稀疏 offload、FP4 跨节点传输共同推进长上下文和分离式 serving；rc1 默认切到 V2 与 Python transceiver。

三、最 Tricky 的 Fixed Issues：根因与方案

3.1 KV 传输、退休与内存所有权

1. #19545 · “传输 SUCCESS”却将未写完整的 KV 放入复用树

rc0 / 跨请求污染

静默污染 写入被跳过、部分完成或误路由时，结果仍可返回 SUCCESS。原请求可能正常，但坏页以 prompt token hash 进入 radix reuse tree，污染之后同前缀请求。

根因传输结果只证明协议完成，不证明目标物理页被完整、唯一地覆盖；少写不安全，多写也可能意味着重复或误路由。
方案sender 对“实际完成 submission 的字节数”做 attestation，而不是报告计划写入量；receiver 要求与发布目标字节严格相等，少写、多写、未知均拒绝。各 rank verdict 在现有 outcome allgather 中取交集，不新增 collective。

验证采用 fail-closed：未验证只禁止进入复用树，不影响当前生成。CPU mock 覆盖 false-success、short/over/unknown coverage。边界：同步多 rank 路径仍被审查指出可能只用本地 verdict。

2. #19673 · RetirementWatchdog：逻辑请求结束不等于物理所有权已结算

rc0 / 所有权生命周期

迟到访问 失败、取消、超时或 shutdown 后，backend/远程访问可能仍在使用 KV/AUX；BACKEND DONE、暂时空 claim set 或 late completion 都可能被误当作可复用证据。

根因逻辑结果与物理所有权被放在同一生命周期里处理；可重置 deadline 或暂时无 claim 会让“等待安全”无限延长或提前结束。
方案RetirementWatchdog 串行化 expose→claim→settle/fatal，宽限期不可重置，逻辑终态不可被 late success 改写。到期只锁存 UNPROVEN_FATAL 并隔离，时间本身从不授权释放。

81 个 deadline 用例；七套件 317 passed/1 skip。边界：rebase 后未重跑，GPU/NIXL qualification 未覆盖；进程终止和替换由 #19674 处理。

3. #19674 · 无法证明 quiescence 时选择 fail-stop，而不是普通 cleanup

rc0 / 分布式 containment

安全优先于可用性 取消早于 session 创建或 metadata 已过期时可能永远没有 ACK，迟到 session 还可重新 admission；此时回收 KV 会让迟到访问命中已复用内存。

根因缺失 ACK 不能解释为“没有访问”，超时也不能证明 GPU/RDMA 已排空；普通异常清理在分布式所有权下并不安全。
方案持久 request-ID fence 阻止旧请求重入；所有已发布 writer 排空后按序返回 SESSION_QUIESCED。固定 deadline 后仍无法证明时保留资源，通过预捕获 MPI communicator 强杀 executor world，日志最多等待 0.5 秒。

x86/ARM 各 206 项通过。代价：MPI abort 可能终止整个 job，fence 元数据随取消 ID 增长；进程终止本身仍不能证明 GPU/RDMA revocation，自动安全替换不在覆盖范围内。

4. #19869 · 禁用 cyclic GC 后，PyZMQ 异常环保留后续 IPC payload

rc0 / Python 内存生命周期

Host OOM 非阻塞 receive 失败留下 Future→exception→traceback→frame 环，frame 又持有后续 payload；服务为性能禁用 cyclic GC 后，引用计数无法打破该环。

根因泄漏不是单个 payload 忘记删除，而是 PyZMQ Future、异常 traceback、frame 与 GC 策略共同形成的保留链。
方案先检查 POLLIN 再接收；stale readiness 引发 zmq.Again 时清空 exc.__traceback__，并把异步 poll 移出 exception handler，避免重建异常环。

76 passed/5 skip；旧代码负面对照有 4 项 retention 失败。未重放 GLM-5.3/GB300 生产负载，也不是 RSS 长时间 soak 测试。

5. #18310 · DLPack 借用指针、空 deleter 与无限 shutdown

rc1 / Capsule 所有权

UAF + shutdown 卡死 consumer 获得 ctypes-owned metadata 的借用指针而 deleter 为 no-op；worker 交付结果后死亡还会让 proxy.shutdown() 永远等待 future。

根因capsule、wrapper 和导入 tensor 三方的所有权没有“恰好交接一次”；关闭路径又缺少统一时间上限。
方案一次 PyMem_RawCalloc 容纳 managed tensor、shape 和 strides，consumer deleter 负责释放；wrapper 只回收从未消费的 capsule，并依赖规范的 used_dltensor 改名。shutdown 使用共享 180 秒 deadline，超时转 dead-engine teardown。

新增 consumed/unconsumed、strided view 和卡死 future 测试；PR 未提供当前测试运行输出，且 consumer 必须遵守 DLPack 改名规范。

3.2 GPU 异步顺序、流所有权与大地址计算

6. #19581 · KDA prefill 的“完成信号”漏掉仍在读 Q/K 的 K1 warps

rc0 / Stage 复用竞态

同输入不同输出 TMA 在 K1 Pass 2b 仍读取共享 Q/K 时提前覆盖 stage，导致输出与 recurrent state 不确定。

根因k1_done 只表示 cumsum 完成；原 stage-reuse barrier 只等 10 个 MMA warp，没有等待另外 16 个 K1 reader warps。
方案把 K1 readers 纳入 stage-reuse arrivals，并覆盖首次 pre-arrival；K1 只有在 Pass 2b 实际读完 Q/K 后才 arrive，TMA 必须等 K1 和 MMA 两组读者。

B200 15 项通过；eager/CUDA graph 各连续 128 次逐位一致。验证是 kernel-path overlay，不是完整 native-main 构建。

7. #19829 · Kimi attn_res 同时存在 WAR 与 generic/async proxy 竞争

rc0 / 双重同步缺口

罕见错值 多 chunk 时慢 warp 仍读 ws_stats，快 warp 已写下一块；generic-proxy shared loads 与后续 TMA async-proxy refill 之间也缺少 fence。

根因named barrier 只保证“写完再读”，不保证“读完再写下一 chunk”；普通 warp sync 也不能建立两种 proxy 之间的内存可见性。
方案按 chunk parity 双缓冲统计区，避免增加全局 barrier；release 前 __syncwarp()，每个读线程执行 fence.proxy.async.shared::cta，使顺序不依赖指令调度。

480/480 点逐位一致，79,296 个 WAR hazard 降为 0；原生运行曾 0/200 复现。persistent kernel 的双缓冲仍留待后续。

8. #20064 · Speculative beam D2H 路径同时缺少 allocator 与 CPU 同步

rc1 / CUDA stream 所有权

崩溃 / 坏状态 side-stream 异步拷贝期间 caching allocator 可复用 source；另一路径 CPU 在 non-blocking D2H 完成前读取 pinned host beam history。

根因PyTorch allocator 只凭原 stream 判断 tensor 可复用，不知道 side stream 仍读；non-blocking copy 又没有和 CPU 建立 happens-before。
方案对源 tensor 调用 src.record_stream(side_stream)，延长存储生命周期；builder 读 host 前同步 current stream，并仅在全部 beam 结束时调用，避免每一步都付同步成本。

新增 CUDA 单测并手测 Qwen3-1.7B 不再崩溃；自动审查指出竞态测试缺少独立执行结果，不能把“测试已添加”当成“全部通过”。

9. #20190 · 目标是 int64，乘法却已经先在 32 位溢出

rc1 / 大上下文地址计算

静默越界写 超过 32 个 1M-token context requests、行号达到 2²⁵时，gather 越界写、scatter 错读，且没有错误提示。

根因token_idx * 64 的两个操作数均为 32 位，表达式先按 32 位计算并回绕；即使结果随后存入 int64_t，也无法恢复正确地址。
方案gather/scatter 的 payload 与 scale 路径都在乘法前把 token_idx 转为 int64_t，而不是只扩大目标变量。

GB300 47 项通过，最高验证 268,439,040 行；未新增常规单测，因为复现需要超过 2 GiB cache 加一份 gathered copy。

10. #20221 · Helix all-to-all 把 FIFO flag 当数据，特定位型变成 NaN

rc1 / Proxy 可见性

约 2×10⁻⁹/entry 损坏 cp=16、跨 NVL72 trays 时偶发 NaN；错误 u64 总位于 LL128 flag slot且等于调用步数，说明收到的是 flag 而非恢复后的数据。

根因protoUnpack 用 generic-proxy stores 恢复数据，随后 cp.async.bulk 以 async-proxy 读同一 shared memory。PTX 要求两者之间 proxy fence，只有 __syncwarp() 不足。
方案在 unpack 与 s2gAllFields 之间加入 fence_view_async_shared() 和 warp sync，确保 bulk read 看到恢复后的字，而非 FIFO step。

约 1.26×10¹⁰ entries 压测由 23/20 个损坏降至 0，另一 600 秒测试 28→0。回归用 SM100/103 单 GPU 模拟四 rank，不是原始 16-GPU 拓扑。

四、可复用的工程经验

问题模式必须守住的不变量推荐验证
分布式 KV 传输协议成功、实际字节覆盖、各 rank 复用共识是三个不同命题。false-success、short/over-write、误路由、多 rank verdict 分歧。
请求取消与退休逻辑完成不释放物理所有权；只有排空证据能授权复用，超时不是证据。无 session、过期 metadata、late completion、取消后重入、固定 deadline。
CUDA 多 streamallocator 生命周期与 CPU/GPU happens-before 必须分别建立。side-stream copy、提前释放 source、non-blocking D2H 后立即读 host。
GPU proxy / barrierwarp/barrier 同步线程，不自动保证 generic 与 async proxy 的内存可见性。racecheck、强制延迟、压力kernel、逐位对比；原生不复现不代表无竞态。
大索引地址计算在第一次乘法前提升位宽，而不是仅把最终结果存入 64 位。2²⁵/2³¹边界、payload与scale两条路径、真实大buffer认证。
Python / DLPack 所有权异常环要显式打破；跨语言对象必须明确由谁、在何时释放一次。禁用GC负面对照、consumed/unconsumed、strided view、worker快速死亡。
P0 · 生产采用：本月能力都在 RC/main。若必须生产使用，固定到具体 RC commit，不用浮动 main；重点验证 rc1 默认 KV cache manager V2/Python transceiver、流式取消和分离式传输。rc1 已知问题包括 A100 上流式取消后的 KV transfer error，以及 Qwen3 JSON-schema 示例可能返回无边界响应。
P0 · 构建与迁移：rc29 移除 AutoDeploy 和 CMake cpp_only，并升级 PyTorch 2.14、Triton 3.8、C++20；rc1 又用 std::span 替换 C++ ArrayView，并移除部分 LlmRequest 字段。插件和自有构建脚本需要先适配。
P1 · 性能评估：FP4 KV 的 TPOT 收益伴随 TTFT 成本；PrimTS 原生稀疏 MLA 的默认路径可能带来显著冷启动开销；VisualGen、MoE router 等加速比都绑定具体模型和形状。应同时记录 TTFT、TPOT、E2E 吞吐、冷启动与精度。

五、术语速查

KV Cache Manager V2新一代 KV 块、分层存储、复用和传输管理体系。Disaggregated serving将 prefill/context 与 decode/generation 分离部署，通过传输层共享 KV。
MLAMulti-head Latent Attention，多头潜在注意力，以低秩表示降低 KV 开销。NVFP4 / FP84-bit / 8-bit 浮点或微缩放格式，可压缩权重、激活或 KV。
DSpark / MTP草稿与多 token 预测路径；目标模型验证并接受或拒绝候选 token。MoEMixture of Experts，混合专家；每 token 只激活部分专家。
TMA / async proxyTensor Memory Accelerator 及异步内存访问代理，和普通 load/store 的可见性规则不同。WARWrite After Read，前一读尚未完成就被后续写覆盖。
Quiescence相关访问已排空、没有再使用资源的活动状态；必须有证据，不能由超时推断。DLPack跨框架张量交换协议，capsule 名称与 deleter 决定所有权交接。
TPOT / TTFT后续每 token 时间 / 首 token 时间，需分别评估。PrimTS / VisualGen高性能注意力内核路径 / TensorRT-LLM 的视觉生成模型子系统。
