0结论与范围

保留现有 manager / backend / codec / DM / 历史边界，先校准事实，再按证据补缺口。生成约束值得评估，但不能以改变 nlu_10、削弱解析门或迁移历史 owner 为代价。本次讨论已明确：保留 nlu_10、单次模型调用、不自动重试；失败计数并进入既有兜底。此处仅更新文档，不代表代码已实现或获准开发部署。

原讨论中的“marker 行 + JSON 体”“采样参数写死”“没有 HTTP 超时”和“全候选门意味着多次生成”与参考基线不一致。本版纠正这些前提，保留可靠性议题，撤下未经生产证据支持的 P0/P1/P2 故障分级。

  • 当前文档工作：纠正叙述、同步图文、明确证据和待决项；不授权实现或外部操作。
  • 保留不变量：完整有界输出、严格整组解析、既有业务和历史准入、每 session 正常轮次串行、不同 session 可并发。
  • 当前明确不做：不新增 JSON codec，不做自动重试或反馈式再次生成；Android 引擎统一、训练及全管线替换也不在本次范围内。

证据分层：参考文档中的 CODE / CONTRACT 标记属于其固定修订，不自动成为本次的 CODE-CONFIRMED 或 RUNTIME-CONFIRMED 结论。原稿对 llama.cpp master、TensorRT-LLM、LLaMA-Factory 的概括不作为当前部署能力证明；后续引用须固定版本、接口与所选路径。

3单次调用、失败分类与预算

讨论已明确的文档方向：一个既有 DM 兜底流程，保留不同的内部原因。模型返回 unknown、格式错误和推理超时，都可以收敛为业务上的“无可用语义”，交给既有 DM 拒识/兜底流程。不为三类原因新建三套 DM 机制。取消不属于这条统一兜底路径。

格式错误与超时分别指什么？

  • 格式错误：模型已返回文本，但不符合所选 nlu_10 协议，例如返回自然语言解释、缺少必需字段，或 multi:music<TAB>pause; 存在尾部空帧。结构合法但业务含义错误，不属于格式错误，仍由既有语义/业务处理判断。
  • 超时：连接或推理调用超过配置时限，未能及时取得可接受结果；不是模型回答了 unknown。
  • 合法 unknown：模型确实按协议返回拒识结果；其来源与格式错误、超时不同，但用户侧可使用同一兜底响应。
有效语义 ──────────────────→ 既有正常 DM
模型返回 unknown ─┐
格式错误 ─────────┼───────→ 同一既有 DM 拒识 / 兜底
推理超时 ─────────┘
取消 ─────────────────────→ 独立终止与清理

优先使用既有状态/错误字段和诊断日志保留原始原因，不因此要求新增结果类或框架。不要把失败的原始输出替换成字符串 unknown 再送 parser，伪装为模型成功返回。业务结果可以统一，原始证据和成功/失败统计不能混淆。

统一兜底不执行无效或部分语义，不向模型历史写入伪造的成功语义；是否保存 Query 仍由既有历史准入决定。此处记录的是讨论方向，不代表现有代码已完成上述映射，也不授权产品修改；当前实现需另行核对。当前方向明确不自动重试；失败不触发新的模型调用。

单次调用与预算边界

  • 一次的范围：同一次准入处理进入真实 LLM 路径、且请求构建成功后，只发起一次模型调用。不二次采样、不附加失败反馈重发、不换模型补发。hotfix/mock、构建失败或调用前取消可能为零次调用，不应为满足“一次”强行调用。
  • 全链路核对：后续实现核对需涵盖 Dialogue/backend、HTTP 客户端、代理及 provider 的自动重试配置。应用层没有重试循环不等于全链路没有隐藏重试；当前文档不宣称它们已关闭，也不授权调整这些组件。
  • 时间预算：沿用已有 connect/total timeout；如补端到端 deadline，先定义起点、排队、单次推理、解析、兜底及完成阶段的预算。使用单调时钟，不在失败后重置时限，不使用半预算守卫来准入第二次调用。
  • 能力边界：如果 SDK 无法中断，就不能承诺硬完成上界。客户端停止等待与引擎停止生成须分别验证；不得允许晚到 callback 绕过现有 offline 同步完成合同。

容量理由：简化示例中，100 个需要推理的业务请求若有 10% 再调用一次，会变成 110 次模型调用；这不是实测数据，也未计入输入/输出 token 差异。当前选择用失败统计定位问题，避免重试加重排队和尾延迟；扩容应由 QPS、并发、资源利用率和延迟证据驱动，不是看到任意失败就扩容。

历史提交不能移到 ParseResponse

参考文档描述的完成路径包含历史准入评估、Turn 存储、可选流式发布/等待，以及合格 Query 存储尝试；Query 写回还要求 frame 所有权转移和 AfterProcess 成功。失败的模型调用不自行写历史，不等于“一个逻辑请求一定写一条历史”。写入与容量淘汰也不能假定原子：HSet 成功后 HDel 失败可能留下部分变化。存储错误不能一律解释为“没有写过”，也不能触发新一轮模型调用。

5解析与观测边界

  1. backend 结果：HTTP 检查状态/envelope 并提取正文；offline 复制有界的完整或有序增量文本。provider 返回前完成全部 callback，不接收晚到回调。
  2. 既有包装处理：沿用 codec 已有规则；遇到截断或不完整内容不能捏造完整语义。
  3. wire 验证：按 single / unknown / multi 与精确风格解析所有帧；拒绝混合风格、空帧和不完整结果；不能静默跳过坏帧。
  4. 语义交接：进入既有 SemanticFrame / SlotNormalizer / DM；不新增标签白名单或独立动作模型。槽值 a|b 保持字符串，不自行拆成多动作。
  5. 完成与历史：由既有 owner 决定准入、提交和清理；模型输出不等于最终业务真相。

严格 parser 始终是安全边界。即使约束采样可用，也可能出现截断、provider 不支持字段或契约不一致；合法结构不代表正确动作。不能把解析门降格为形式校验。

观测目的复用机制边界
阶段耗时现有 request-owned Timeline。先核对 API、时钟、区间语义和覆盖；不增加平行 stopwatch 或 session 复用累积器。
诊断已有 LOG / VLOG；详细内容使用 VLOG(4)。debug 的原始业务 JSON 复用现有边界；release 不打印 payload、history 或 prompt。认证 header 与 body 分开。
聚合质量与性能已有 PrometheusWrapper，能力/初始化核对后补缺口。固定低基数 outcome/reason；不使用 request/session ID 作标签。明确 NLU 终态计数 owner，backend、manager、DM 不重复累计同一失败；兜底响应成功不覆盖原始技术失败。
重要生产事件仅在现有 schema 和 owner 允许时使用 LogReporter。不为阶段日志新增 Kafka 事件，不把 Linux 依赖带入 Android。

评估至少区分：格式失败、合法拒识、错误动作、合法多意图接受、history 正确性、p95/p99 延迟。没有重试路径，不增加重试率或修复成功率指标；不预设格式错误下降若干数量级。没有运行样本时，这些是未来评测维度，不是本次结果。

cancelled请求被取消并进入清理；不混成超时。独立分类，不混入上述故障数
  • 不重复累计：同一次准入处理的 NLU 终态只计一次；底层返回原因，最终 owner 计数。HTTP 失败若导致正文不可解析，应按已确定的服务错误计数，不再叠加一个格式错误。
  • 不掩盖失败：DM 成功生成兜底话术不把 NLU 技术失败改计成成功。原始模型输出和错误证据保留在既有诊断边界，不伪造 unknown 正文。
  • 不增加平行框架：优先使用现有终态计数的固定 outcome/reason；失败总数可由对应分类聚合，不机械新增重复计数器。request/session ID、原始文本、URL、任意错误字符串不得作为指标标签。
  • 分类驱动改善：格式失败关注模型输出与 descriptor 匹配；超时结合排队、QPS、并发和资源利用率分析；传输/服务错误检查调用链。更多算力不直接修复格式错误，失败计数本身也不是修复措施。
