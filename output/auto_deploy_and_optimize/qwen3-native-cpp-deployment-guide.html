Why a verified archive seed helps

The build runner deliberately creates fresh HOME, Bazel output, install, repository and action-cache directories for every stage. The v2 correction preserves that isolation: an explicitly prepared, immutable seed contains verified dependency archives, not compiled outputs, model weights, a JDK installation or a live shared cache. Each supervised stage independently copies those archives into its own new repository cache; Bazel still checks the hashes declared by its dependency definitions. Seeding is optional and does not select a different compiler, SDK or model. Tooling checks, explicit seed preparation and the real test/build/model acceptance sequence have passed. 硬件决定后端，不能把所有 GPU 都叫 CUDA

NVIDIA 通常选择 CUDA；Intel Arc / Intel 集显可评估 SYCL 或 Vulkan；AMD 可评估支持该卡的 HIP/ROCm 或 Vulkan。Android GPU 需按 SoC、驱动和可用后端另测；NPU 属于不同的加速器路线。以上是后端候选，不代表当前 pin 已在你的设备验证。上游后端说明、SYCL 说明。

三个独立维度：CPU/GPU 决定计算设备；F32/Q8 决定权重表示；进程内/HTTP 决定接入方式。应逐项比较，避免同时换设备、量化、引擎和 prompt 后无法定位差异。

配套计划详见 GPU 独立集成计划。建议先做单设备、单请求的原生 GPU 验证；如果真正目标是多会话服务吞吐，再单独评估 GPU 服务。TurboMind 的批处理机制属于服务引擎能力，不是 GPU 硬件自动赋予当前 provider 的能力。TurboMind 官方架构。
