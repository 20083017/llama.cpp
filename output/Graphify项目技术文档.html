Graphify 项目技术文档

Graphify — 把任意代码库（含文档、SQL Schema、配置、PDF、音视频）变成可查询的知识图谱，供 AI 编程助手通过 /graphify 使用。

1项目定位：是什么 / 不是什么

Graphify 由 Claude Code skill 编排、Python library 实现（library 也可独立使用）。它把整个项目（代码、文档、PDF、图片、音视频）映射成一张真实可遍历的知识图谱，让 AI 助手"查询图谱"而不是反复 grep / 读文件，从而大幅降低 agent 的 token 消耗（官方宣称 Graphify Cloud 可省 80%）。

维度是不是
检索方式图遍历（query / path / explain），每条边有解释不是向量检索：no embeddings、no vector store
代码解析tree-sitter AST，本地确定性解析，无 LLM 参与不是 LLM 猜测式代码理解
覆盖范围约 40 种语言的跨文件关系（calls/imports/inherits/mixes_in）+ 文档/媒体不只是代码索引工具
交付形态本地 CLI + /graphify skill + MCP server + Cloud 服务不是 SaaS-only（本地优先，code-only 可完全离线）
三大卖点（README 原文）：① Code maps for free, fully local — 代码解析不出本机；② Every edge is explained — 每条边带 EXTRACTED / INFERRED 置信标签；③ Not a vector index — 真图遍历，可问答、可追踪路径、可解释概念。

2快速上手

# 安装（需 Python 3.11+，uv 或 pipx；PyPI 包名 graphifyy 双 y）
uv tool install graphifyy        # 或 pipx install graphifyy
graphify install                 # 自动检测你的 AI 助手并注册 skill

# 在 AI 助手中（Claude Code / CodeBuddy / Cursor / Codex / Gemini CLI）
/graphify .                      # 为当前目录建图

运行后生成三个产物（输出目录 graphify-out/）：

graph.json完整图谱数据，可随时查询而无需重读文件

3核心数据流水线（架构）

各阶段独立成模块，中间用 plain Python dict 与 NetworkX 图通信，尽量减少共享状态：

模块职责表

模块入口职责
detect.pydetect(root)目录 → 扫描摘要 dict（按类别分组 files、total_files/total_words）
extract.pyextract(paths, *, root) / collect_files()统一抽取入口；目录展开为文件列表；dispatch 按后缀路由 extractor
build.pybuild(extractions) / build_from_json()抽取 dict → NetworkX 图；含语义节点折叠与来源保护
cluster.pycluster(G)社区聚类，输出 {community_id: [node_id]}，不改传入图
analyze.py兄弟函数集合god nodes、意外连接、建议问题、import 环、图 diff
report.pygenerate()生成 GRAPH_REPORT.md
export.py按格式兄弟函数json / html / obsidian / svg / graphml / canvas / cypher
wiki.pyto_wiki()每个社区一篇 Markdown 文章 + index.md
cache.pycheck/save_semantic_cache语义缓存，支持增量抽取
security.py四个校验函数所有外部输入的安全边界（URL / 抓取 / 路径 / label）
serve.pyserve() / serve_http()MCP stdio server / HTTP server
watch.pywatch(path, debounce=3)文件变化触发重建

4graph.json：schema 与方向语义

4.1 extractor 统一契约

{
  "nodes": [ { "id": "唯一字符串", "label": "人类可读名", "source_file": "相对路径", "source_location": "L42" } ],
  "edges": [ { "source": "id_a", "target": "id_b", "relation": "calls|imports|uses|...",
              "confidence": "EXTRACTED|INFERRED|AMBIGUOUS" } ]
}
置信标签含义
EXTRACTED源码中显式存在（如 import 语句、直接调用）
INFERRED合理推断（如 call-graph 二次分析、上下文共现）；path 的整体置信度 = 最弱一跳
AMBIGUOUS不确定关系，会在报告中标记供人工审查

4.2 方向语义（易踩坑点）

graph.json 写出 "directed": false，但每条边实际都是有向的。方向由 arc 顺序（source → target）表达；较老的文件边上有 _src/_tgt 标记（优先）。直接用 json_graph.node_link_graph() 加载会丢方向——必须走 paths.load_node_link_graph() 或先 restore_arc_direction()。读方向只能用 data.get("_src", u)，不能从 u, v 读。

5多语言抽取策略

约 40 种语言基于 tree-sitter AST 做跨文件解析。整体哲学是推断极其保守：未知、歧义、被遮蔽、动态、模板依赖的情况大多保持 unlinked，不猜。

语言关键策略
Pythonnested class id 含父类 id；self.field = value 注入字段类型追踪；模块级构造赋值可解析成员调用（INFERRED）
C++receiver chain 解析（裸指针 / unique_ptr / shared_ptr）；别名（using/typedef）带作用域与声明顺序；前向声明/声明-定义折叠需"exact include proof"；条件编译分支按字节保留恢复（不跑预处理器）；继承成员只沿显式可达基类，菱形/虚基类不解析
Javapackage/import 上下文 + 继承成员的词法查找；歧义继承类型不链接
C#partial 类型跨文件按路径合并（含 arity）；构造函数/索引器/运算符独立成节点
Go成员调用经 declared receiver type 解析（INFERRED）；包级裸调用保持 EXTRACTED
JS/TSdefault import 的对象字面量调用复用静态方法节点；词法遮蔽/计算属性/动态别名一律不推断
Kotlin / Swiftnamespace 持久化、限定接收者名保留；先词法作用域再模块级解析
Terraform/HCL节点 id 记录生成时的 scope，缓存命中后重写为当前 scan root 的相对路径
SQL / Postgresschema 抽取 / 活库内省（--postgres DSN）
缓存失效高度显式：多个 AST cache schema 版本（7/9/33/37/40/41/43/47/51…）通过"退役"机制强制重建对应语言的旧缓存，例如 C++ 语义升级后需要 graphify extract . --code-only --force 全量重建。语义来源（rationale / URL / 作者 / 时间）绝不被静默折叠丢弃——含 provenance 的语义节点即使与 AST 节点同名也保持独立。

如何新增一种语言（五步，全部必做）

  1. 在 graphify/extractors/ 新增 extract_<lang>(path) -> dict，遵循 tree-sitter parse → walk → {nodes, edges} + 二次 call-graph 推断的既有模式
  2. 在 extract() 的 dispatch table 注册后缀
  3. collect_files() 同步注册
  4. detect.py 的 CODE_EXTENSIONS 与 watch.py 的 _WATCHED_EXTENSIONS 同步更新
  5. pyproject.toml 加 tree-sitter 依赖 + tests/fixtures/ 加 fixture + tests/test_languages.py 加测试

6Skill 集成矩阵（20+ 平台）

graphify install 自动检测助手并注册 skill；默认装到用户 profile，--project 装到当前 repo（如 .claude/skills/graphify/SKILL.md、.agents/skills/graphify/SKILL.md）。

机制平台说明
Hook 平台Claude Code、CodeBuddy、Gemini CLIPreToolUse hook 在 search 类工具调用前自动提示先查图谱；Claude Code 还会在 Read/Glob 及 cat/head/tail/sed 读取前触发
指令文件平台Codex、OpenCode、Cursor、Trae 等通过 AGENTS.md、.cursor/rules/ 持久化 query-first 指令（Codex 用 $graphify）
Agent 通用Agent Skills（--platform agents）全局 ~/.agents/skills/ 或项目 ./.agents/skills/
原生 guardPigraphify pi guard install：在 read/grep/find 前跑 graphify hook-guard

skill 内容由 tools/skillgen 生成，按"渐进披露"拆分为精简核心（约 615 行）+ 按需加载的 references/，CI 用 drift gate 防止生成物漂移。

CLI skill 与 MCP 的区别：graphify install 只装本地集成，不建 MCP 连接；MCP client 不必然跑本地 CLI query；hosted MCP 连接服务的可能是另一台机器上的图。排障时先分清是 CLI 缺失还是 MCP 连接问题。

9安全与隐私设计

维度策略
代码tree-sitter 本地解析，不出本机；code-only 语料无需 API key、可完全离线（--code-only）
媒体音视频用 faster-whisper 本地转写；docs/PDF/图片的语义抽取会发送给所配后端（自动检测优先级 Gemini → Kimi → Claude → OpenAI → DeepSeek → Azure → Bedrock → Ollama；注意 Kimi 路由到 Moonshot 中国服务器）
遥测No telemetry、no usage tracking、no analytics
输入边界所有 URL 经 validate_url()（仅 http/https，阻 file:// 重定向）；抓取带 size cap/timeout；图路径必须落在 graphify-out/ 内；label 去控制字符、限 256 字符
section 读取限制在项目根内；redact_secrets 脱敏；section 文本不进 graph.json

11采纳路径建议（P0/P1/P2）

级别动作理由
P0在目标代码库跑 code-only 本地建图：uv tool install graphifyy → graphify . --code-only --no-viz → 看 GRAPH_REPORT.md 和 graphify explain/path 的质量零 API key、零成本、零外传，10 分钟内可验证图谱质量是否达标（对 C++ 大型项目尤其要看 receiver/别名解析的实际覆盖率）
P0验证方向语义坑：任何自写消费 graph.json 的代码必须走 load_node_link_graph() / _src_tgt"directed: false 但每边有向"是官方明确的设计坑（issue #563/#2309）
P1接入 CodeBuddy skill：graphify install --platform codebuddy，体验 always-on 的 query-first 工作流 + PreToolUse hook官方支持 CodeBuddy 平台，机制与 Claude Code 相同
P1配置 docs/PDF 语义抽取后端（Ollama 可全本地）；加 graphify hook install 让 commit/checkout 自动重建把文档、ADR/RFC、设计 PDF 并入同一张图，配合增量更新
P2MCP stdio server / 团队共享图 / Neo4j·FalkorDB 导出 / Graphify Cloud（跨仓 monorepo、PR review、Sentry/Jira 连接器）团队级与 SDLC 集成，涉及网络与治理决策，先验证单人价值再上

12术语表

术语全称 / 中文含义
ASTAbstract Syntax Tree，抽象语法树源代码的树状结构化表示，graphify 用它做确定性解析
tree-sitter—增量式语法解析库，支持数十种语言，编辑器领域事实标准
MCPModel Context Protocol，模型上下文协议AI 助手与外部工具/数据源的标准连接协议（stdio / HTTP）
god node枢纽节点连接度最高的概念节点，指示系统核心枢纽
community社区用 Leiden 算法从图中划分出的子系统簇
Leiden / Louvain—两种社区发现算法；graphify 优先 Leiden，无依赖时回退 networkx Louvain
NetworkX—Python 图计算库，graphify 的中间图表示
provenance来源 / 溯源节点的 rationale、来源 URL、作者、采集时间等元数据，受保护不可静默丢弃
ADR / RFCArchitecture Decision Record / Request for Comments架构决策记录 / 征求意见稿；其引用会成为图的一等节点
PreToolUse hook工具调用前置钩子AI 助手在调用某工具前自动执行的拦截脚本
monorepo单一大仓库多项目共存于同一代码仓库的组织方式
