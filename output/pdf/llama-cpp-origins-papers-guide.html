起源：一个周末项目如何成为行业标准

作者 Georgi Gerganov（保加利亚工程师，索菲亚大学物理系背景）的技术脉络：2022 年 9 月起开发 ggml 张量库（灵感来自 Fabrice Bellard 的 LibNC，设计目标是严格内存管理 + 零运行时分配 + 多线程），先用它做了 whisper.cpp（OpenAI Whisper 的纯 C/C++ 移植）证明了"认真对待内存布局，消费级 CPU 也能跑严肃神经网络"。

2023 年 2 月 Meta 发布 LLaMA（限研究许可），数日内权重泄露。Meta 实现依赖 PyTorch + FairScale + CUDA，普通开发者跑不动。Gerganov 用一个周末在 ggml 上重写了 LLaMA 推理全链路：2023 年 3 月 10 日 llama.cpp 首发，7B 模型在 8GB 内存的笔记本 CPU 上可跑。关键的"顿悟时刻"：AVX2 的 256-bit SIMD 寄存器一次装 64 个 4-bit 权重 + 精心布局的内存访问 = 无 GPU 也能达到对话速度。

一周数千 star，迅速成为本地推理事实标准（Ollama / LM Studio / GPT4All 都以它为基座）。2023 年 6 月 Gerganov 创办 ggml.ai（Nat Friedman 与 Daniel Gross 预种子投资）；2026 年 2 月团队加入 Hugging Face 获得长期机构支持，保持 MIT 协议与社区开发模式；2026 年 3 月 GitHub 破 10 万 star（快于 PyTorch 的约 7 年与 TensorFlow 的约 8 年）。

机制来源说明

CPU threadpool项目原创自旋+睡眠混合等待、chunk 原子抢占，为异构大小核而生
llamafile sgemmJustine Tunney (2024.03 合入)x86/ARM 的 FP16/INT8 微内核优化 + Cosmopolitan 跨平台单文件方案

阅读建议：读代码前先看论文"贡献"列建立概念，再到"实现位置"列对照——这比直接啃源码快数倍。量化主题的论文与《转换量化指南》互为理论与操作的两个面。

生态位与选型含义

维度llama.cpp对照（vLLM / TensorRT-LLM）
定位本地/边缘/混合推理事实标准，零依赖单二进制数据中心吞吐优先，Python 栈绑定
强项消费硬件 CPU、Apple Metal、量化格式生态(GGUF)、便携性PagedAttention 类显存管理、高并发吞吐、CUDA 深度优化
被谁依赖Ollama / LM Studio / GPT4All 等几乎所有本地工具云服务商推理 API
对你的场景WTP184 车机（CPU/异构核 + 0.6B 级模型 + 嵌入式集成）恰好落在 llama.cpp 的主场——这也是全部既有文档围绕它展开的原因

版本注记：本工作区为 2026 年新版（tools\server 布局、KV 变体家族、稳定版发布线 v0.x）。网上 2023-2024 的教程（examples\server、GGML_TYPE 老枚举、三阶段任务模型）与本仓库已有结构性差异，以本地代码与本文档序列为准。
