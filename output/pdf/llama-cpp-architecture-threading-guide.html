总体架构：三层解耦

图 1. 三层架构。设计哲学：无依赖纯 C/C++；一切计算表达为张量图；按算子支持度动态切分后端。llama 层与 ggml 层互不知晓对方领域细节，这是整个项目可维护性的根基。

GGUF 与加载流程

GGUF = 魔数 + 版本 + KV 元数据（超参）+ 张量目录（名/维度/dtype/offset）+ 数据 blob，32 字节对齐。加载链：读 gguf → init_hparams（KV 注入超参）→ create_tensor（按目标后端 buft 建张量，支持 LAZY）→ init_mappings（mmap 零拷贝映射）→ load_all_data（src\llama-model-loader.cpp:262）。mmap 使权重不进驻内存、按缺页加载，冷启动与内存占用都受益（src\llama-mmap.cpp）。

加速策略、优化策略与优化方案

优化选型的根本逻辑：量化换内存带宽（decode 是 memory-bound，权重每 token 都要读一遍，这是量化的第一收益）→ batching 换吞吐（prefill 是 compute-bound，多序列拼 batch 摊薄权重读取）→ 投机/流水线换延迟。

级别策略机制与位置适用场景
P0权重量化1.5~8bit 全族（ggml.h:390-433）。K-quants 超块：QK_K=256，两级 scale（超块 d/dmin + 子块 6bit scale），权重 x = a*q + b；Q4_K_M 是质量/速度平衡点；IQ 低比特系列强制需要 imatrix 重要性矩阵（tools\imatrix）。所有场景的地基，详见《转换量化指南》
P0mmap 零拷贝加载llama-mmap.cpp：权重映射文件按缺页读取 + llama_prefetch，冷启动与 RSS 双降。大模型 / 多实例常驻
P0prompt 复用seq_id 体系 + get_common_prefix 最长公共前缀续算（server-common.cpp:818）：多轮对话只 prefill 增量部分。NLU 多轮会话（与网关上下文设计同构）
P1continuous batching--parallel 多 slot，update_slots 每轮拼公共 batch；ubatch 分片（split_simple/equal/seq, llama-batch.cpp）控制单图规模。并发服务吞吐
P1Flash attentionggml_flash_attn_ext（ggml.c:5550）不物化注意力矩阵；CUDA 三套模板（tile/mma/vec）；KV 量化(V→Q8/Q4)强制要求开启 FA（llama-context.cpp:4081）。长上下文必备
P1投机解码--spec-draft-model + --spec-type（simple/eagle3/mtp/dflash/ngram），draft 一次猜 N 个 token，主模型一次验证。单流延迟敏感
P1CPU/GPU 混合--n-gpu-layers：i_gpu_start = n_layer_all+1-n_gpu_layers（llama-model.cpp:1600），超出 VRAM 的层留 CPU，sched 自动切分。模型略超显存
P2算子级 SIMDggml-cpu\arch\ 下 x86 AVX/AMX、ARM NEON、RISC-V RVV 各自实现 vec_dot；repack 重排 GEMM 布局；llamafile sgemm。CPU 推理
P2在线量化激活GGML_PREC_Q8/Q4 tag 允许后端把激活也在线量化，GEMM 走量化 fast path。带宽极限场景
P2KV defrag / K-shift碎片超阈值时重排槽位（llama-kv-cache.cpp:771）；K-shift 用 RoPE 平移实现 context shift（:877）。长会话防碎片
